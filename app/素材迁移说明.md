# 素材迁移说明

现有素材在 `..\site\assets\`（84 个文件、约 8 MB），需要原样复制到 `public\assets\`，
让 URL 路径保持 `/assets/...` 不变。

**在 `app\` 目录下执行**：

```powershell
cd D:\LittleProject\JBYangC\app
robocopy ..\site\assets .\public\assets /E
```

复制完成后：

```
app\public\assets\
├── css\style.css
├── js\data.js
├── js\main.js
└── media\
    ├── 队伍徽章\
    ├── 选手照片\
    ├── 选手印花\
    ├── 选手签名\
    ├── 队服\
    ├── 入场动画\
    └── 合影\
```

## 为什么这份说明不在 public\ 里

`public\` 里的**所有文件都会被原样发布到线上**。我最初把这份说明写成
`public\README.md`，结果 `npm run build` 把它复制进了 `dist\README.md`，
等于把内部说明挂到了公网。

`public\` 只放「浏览器需要直接按 URL 取的文件」：样式、脚本、图片、视频、字体、
`robots.txt`、`favicon`。文档一律放在 `app\` 根目录或 `src\` 下。

## 迁移的后续目标

这三个文件现在是从旧站原样复制过来的，最终要改掉：

| 文件 | 现状 | 目标 |
| --- | --- | --- |
| `assets/js/data.js` | 挂在 `window.JB` 上的全局数据 | 改成 TypeScript 模块，在构建期注入，不打进客户端 |
| `assets/js/main.js` | 用 `innerHTML` 注入导航/页脚 | 改成 Astro 组件，导航直接出现在 HTML 里 |
| `assets/css/style.css` | 全站单文件 | 保留（CSS 变量体系很好），只在需要时拆出组件级样式 |

> 数据层改成构建期注入后，`data.js` 就不该再出现在 `public\` 里 ——
> 它会被编译进 HTML，客户端不需要下载 27 KB 的 JS 才能显示队员名单。
